# 卡卡关系成长可见化与关系人格层 V1 设计

## 背景

当前卡卡已经具备以下基础：

- `relationship.json` 持续记录 familiarity / affection / engagement / trust。
- `memoryManagementService` 已将这些分数映射为 `初识`、`熟悉`、`亲近`、`信赖` 四个阶段，并在 `MemoryPanel` / `PrivacyPanel` 中展示阶段文案。
- `chatService` 已有统一的 DeepSeek system prompt，强调“更关心用户”“可爱但不过分卖萌”。
- `Playful Presence v1` 已让卡卡在聊天后、摸头后、压力聊天后和长时间空闲时产生更有节奏的主动表达。

但当前“关系成长”主要还是内部数值和少量阶段文案，用户能感觉到卡卡在变亲近的地方还不够多。聊天回复、主动气泡、安慰语气和提醒语气仍然偏统一，没有真正形成“关系越深，卡卡越像固定人格地贴近你”的体验。

## 目标

1. 让卡卡的关系成长变成用户能明显感知到的体验，而不只是后台分数变化。
2. 让 `初识/熟悉/亲近/信赖` 四个阶段具有明确、稳定、可识别的人格差异。
3. 在不改成长算法的前提下，让聊天回复、主动气泡、安慰/提醒语气随关系阶段变化。
4. 保持“中等偏强”的亲近感：明显更熟、更贴近，但不过度卖萌或持续黏人。
5. 保留边界感，不引入越界的拟人化表述或隐私越权表述。

## 非目标

- 第一阶段不重做 familiarity / affection / engagement / trust 的成长算法。
- 不新增经验条、签到、等级奖励、成就等游戏化关系系统。
- 不新增大型独立 UI 面板或新的持久化数据文件。
- 不在这一版直接重构完整聊天人格系统；该项是下一阶段工作。

## 方案选择

本轮考虑三种方向：

1. `阶段化话术层`
   只让聊天回复、主动气泡、提醒语气变化。
2. `话术层 + 轻提示 UI`
   在阶段化话术基础上，再加少量界面提示强化感知。
3. `完整关系人格层`
   统一定义四个阶段的人格 profile，同时接入聊天、主动气泡、安慰和提醒。

本设计采用 `完整关系人格层`，原因是：

- 用户已经明确希望先做“更熟后更自然贴近”的整体变化，而不只是某一类文本变化。
- 当前关系阶段、主动陪伴和聊天系统都已经存在，适合用一个统一的 stage profile 把这些入口串起来。
- 这条路线可以自然衔接后续“聊天人格升级”，不会造成两套相互割裂的话术系统。

## 用户可见行为

### 1. 四段人格递进

四个关系阶段继续使用现有 `new/familiar/close/trusted` 推导，但每个阶段要有清晰的气质差异：

- `初识`
  - 礼貌、轻柔、偏克制。
  - 回应更谨慎，更像刚认识你时的陪伴。
- `熟悉`
  - 更自然，更愿意主动接你的情绪。
  - 开始表现出熟络感，但不会明显撒娇。
- `亲近`
  - 明显更贴近，会有一点撒娇感和依赖感。
  - 主动表达更像熟悉你之后的小宠物，而不是泛化助手语气。
- `信赖`
  - 主动关心更稳定，语气最熟络。
  - 允许更明显的“我会陪着你”“我想继续待在你旁边”这类表述，但仍然克制。

### 2. 三条可见通道一起变化

关系成长不只体现在一个地方，而是至少同时作用于三类输出：

- 聊天回复：同一个问题，在高阶段会更熟、更贴近、更像固定人格。
- 主动气泡：聊天后、摸头后、长时间空闲后的主动表达更贴合阶段气质。
- 安慰 / 提醒：压力大、夜间、工作太久等场景下，语气会随着关系成长变得更自然和贴近。

### 3. 中等偏强，但不过界

这一版的人格变化目标是“明显能感到卡卡越来越熟”，但不做成：

- 持续撒娇。
- 每句话都过度卖萌。
- 一直黏着你、不分场景地主动刷存在感。

工作中、夜间和压力场景仍然保持克制，优先温柔陪伴，而不是强行活泼。

### 4. 不游戏化

关系成长仍然主要靠现有 familiarity / affection / engagement / trust 的累积来体现，不新增：

- 经验条。
- 明显数值奖励反馈。
- 打卡、签到、成就、升级提示。

## 实现边界

### 保持现有关系算法

- 沿用当前 `memoryManagementService` 的阶段推导逻辑。
- 第一阶段不改变分值增长方式，只改变“阶段如何影响人格表现”。

### 增加统一 stage profile 规则层

- 新增单独的人格配置 / 规则模块，集中定义四个阶段的差异。
- 该模块输出的不是最终 UI，而是面向聊天、主动气泡和提醒系统的语气配置。

### 先不大改 UI

- 第一阶段重点是“说话方式真的变了”。
- UI 只做轻量文案配合，例如让现有阶段描述更有温度；不新增大型关系系统界面。

### 先接三个主入口

- `chatService` / `chatCoordinator`
  - 让聊天回复更符合当前关系阶段的人格。
- `playfulPresence` / `presenceService`
  - 让主动气泡、安慰和提醒按阶段变化。
- 现有阶段说明文案
  - 做少量更有感情的 copy 优化，帮助用户更容易把“数值阶段”理解成人格阶段。

### 保留边界感

即使进入 `信赖` 阶段，也必须继续遵守：

- 不声称读取用户文件、代码、屏幕、浏览器、终端或隐私信息。
- 不做过度依附、占有欲或情感绑架式表述。
- 不以“更亲近”为理由增加打扰频率。

## 模块设计

### Relationship Persona Profile 模块

新增一个统一的人格配置模块，例如 `relationshipPersona.ts`。它至少需要按阶段输出：

- 聊天语气基调。
- 主动气泡贴近程度。
- 安慰语气柔软程度。
- 提醒语气克制度。
- 可选的称呼 / 自称风格。

这个模块是第一阶段的核心边界：

- 其他模块不各自硬编码“初识应该怎么说、信赖应该怎么说”。
- 所有人格差异都从这里读取，保证后续演进时一致。

### Chat 路径接入

`chatService` 目前有固定的全局 system prompt。第一阶段需要把当前关系阶段的人格 profile 编入 prompt / memory context，使 DeepSeek 在不同阶段表现出不同熟络程度。

目标不是让模型自由发挥，而是通过结构化约束控制：

- 当前阶段的贴近程度。
- 当前阶段是否更主动安慰。
- 当前阶段是否允许轻微撒娇感。
- 无论什么阶段都要遵守的隐私边界和克制规则。

### Playful Presence / Presence 路径接入

`playfulPresence.ts` 与 `presenceService.ts` 负责主动表达和低频提醒。它们需要使用同一份 stage profile，让：

- 聊天后跟随气泡按阶段变化。
- 摸头后亲近气泡按阶段变化。
- 压力场景的安慰文案按阶段变化。
- 长时间工作提醒按阶段变化，但保持克制。

### 轻 UI 配合

现有 `stageLabel` / `stageDescription` 已经存在。第一阶段只需要少量增强：

- 文案更像在描述卡卡的性格变化，而不只是抽象阶段名。
- 不额外增加复杂控件或新入口。

## 数据流

### 聊天回复

1. 读取当前 `relationship`。
2. 根据平均分映射出当前阶段。
3. 从 stage profile 取出当前阶段的人格约束。
4. 将人格约束与现有全局 prompt、用户档案和记忆上下文一起注入聊天请求。
5. 返回更符合阶段的回复风格。

### 主动气泡 / 安慰 / 提醒

1. `presence` 或 `playfulPresence` 判断当前是否应该表达。
2. 读取关系阶段对应的人格 profile。
3. 按阶段选择更合适的语气模板。
4. 输出仍受夜间、工作中、冷却等现有规则约束。

## 测试策略

第一阶段优先新增单元测试，覆盖：

1. 不同关系阶段返回不同的 persona profile。
2. 聊天 prompt 能带上阶段人格约束，而不是只用固定全局 prompt。
3. 主动气泡文案按阶段变化。
4. 安慰 / 提醒文案按阶段变化。
5. `trusted` 阶段可以最亲近，但仍然不越界。

如果现有测试已经覆盖 prompt 关键字和阶段文案，需要在保持原有隐私约束不回归的前提下扩展断言。

## 成功标准

1. 用户能明显感觉到卡卡在关系变深后说话更熟、更贴近。
2. 聊天回复、主动气泡和安慰 / 提醒至少三条通道都体现阶段差异。
3. `信赖` 阶段最亲近，但仍然保留边界感和克制。
4. 不引入新游戏化系统，不改变现有关系成长算法。
5. 相关定向测试、全量测试和构建验证通过。

## 后续演进

这一版完成后，下一阶段可以顺势继续做：

- 更完整的聊天人格升级。
- 更细的称呼策略和上下文记忆联动。
- 更丰富的关系阶段专属主动行为。

但这些都不纳入本次 V1 范围。
